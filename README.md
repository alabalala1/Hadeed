# Hadeed — حديد

تطبيق Flutter للأندرويد باللغة العربية، يعمل محليًا دون حساب أو خادم.

الإصدار 0.1.3: زر مباشر لعرض صورة التمرين مع التكبير أثناء الجلسة وفي المكتبة، ألوان أخضر داكن وأخضر فاتح لجميع الصفحات، وبطاقة اليوم بعرض كامل مع الإعدادات داخلها.

## المنفذ حاليًا

- مكتبة التمارين: بحث وتصنيف وإضافة وتعديل وأرشفة واستعادة وصور محلية.
- جدول الأيام وتفاصيل اليوم، مع إضافة الأيام وإعادة ترتيبها وتعديل أسمائها وأرشفتها.
- ربط التمارين بالأيام وتعديل أهداف كل جولة والراحة والسوبر سيت والملاحظات.
- قالب قائمة المستخدم: 6 أيام، 40 تعريف تمرين، و41 ربطًا بالأيام.
- نطاقات التكرار محفوظة، والكارديو نشاط واحد اختياري لمدة 30–45 دقيقة.
- حفظ مباشر في SQLite، وترقية البيانات السابقة دون مسحها.
- خط Cairo وأيقونات Figma محلية، وواجهات عربية RTL.

يُضاف القالب مرة واحدة؛ تعديلات المستخدم تبقى عند إعادة فتح التطبيق.
الخطط تخص كل يوم، حتى لو تكرر التمرين نفسه في أيام أخرى.
الجلسات الفعلية والجولات والمسودات والمقارنة بآخر أداء والمؤقت والسجل والإعدادات والنسخ الاحتياطي منفذة.
تُستكمل الجلسة بعد إعادة الفتح، وتنتقل الدورة بعد تأكيد الإنهاء فقط.

## التشغيل

ثبّت Flutter stable (3.44 أو أحدث)، مع Android SDK وJDK 17:

```sh
flutter pub get
flutter analyze
dart run tools/check_repository.dart
dart run tools/check_training.dart
dart run tools/check_workout.dart
flutter test
flutter run
```

إعدادات Android مبنية على قالب Flutter 3.47.5. المعرّف الأولي
`ye.hadeed.hadeed` والتوقيع الحالي للتطوير فقط.

نجح تحليل Dart و145 فحص SQLite: 14 للمكتبة و54 للخطط و77 للجلسات والمؤقت والنسخ الاحتياطي.
نجح أيضًا اختبار Flutter للواجهات وبناء APK للمعماريات الثلاث في
[التشغيل المختبر](https://github.com/alabalala1/Hadeed/actions/runs/37762913300)،
من كود الإصدار `1ed185cd`. الاختبار يفتح البطاقات العشر ويسجل ويعدل جولة في التمرين الثاني وينهي الجلسة من الواجهة. راجعت لقطات اليوم والجلسة والسجل والإعدادات، ومنها شاشة الجلسة الجديدة على شاشة صغيرة مع تكبير النص. فحوص وقت التمرين تشمل ثباته عند إعادة الاختيار وإغلاق قاعدة البيانات، وإيقافه عند الإنهاء واستعادته من النسخة الاحتياطية.
اختبار إشعارات الخلفية وقفل الشاشة والاستعادة على هاتف فعلي ما زال مطلوبًا.
اختبار الصورة يفتح المرفق من المكتبة ومن الجلسة ويتحقق من بقاء المسودة، ومن ظهور صورة أُضيفت بعد البدء دون تغيير لقطة الجلسة.
التفاصيل في `docs/STEP_04.md` و`docs/STEP_05.md` و`docs/STEP_06.md` و`docs/STEP_07.md` والدليل في `docs/GYM_APP_SPEC.md`.

## تحميل APK من GitHub Actions

يعمل workflow `Build Android APKs` عند كل تحديث لفرع main، أو يدويًا من
Actions → Build Android APKs → Run workflow. يجري تحليل Flutter وفحوص SQLite
ثم يبني Release باستخدام `--split-per-abi`.

بعد نجاح البناء افتح صفحة التشغيل وانزل إلى Artifacts، ثم حمّل الملف المناسب وفك الضغط:

| الملف | المعمارية | حجم APK المختبر |
| --- | --- | --- |
| [Hadeed-arm64-v8a](https://github.com/alabalala1/Hadeed/actions/runs/37762913300/artifacts/11542804398) | ARM 64-bit | 20.0 MB |
| [Hadeed-armeabi-v7a](https://github.com/alabalala1/Hadeed/actions/runs/37762913300/artifacts/11542569976) | ARM 32-bit | 17.6 MB |
| [Hadeed-x86_64](https://github.com/alabalala1/Hadeed/actions/runs/37762913300/artifacts/11543133230) | x86 64-bit، ومنها محاكيات Android | 21.5 MB |

الملفات تبقى 30 يومًا. يعرض ملخص التشغيل حجم كل APK، ورقم البناء يتزايد مع التشغيل.
التوقيع الحالي للتطوير، ويُنشأ على runner؛ قد يلزم حذف النسخة السابقة إذا تغير المفتاح.
صدّر نسخة .hadeed من الإعدادات قبل الحذف، ثم استعدها في النسخة الجديدة.
قبل الاستخدام المستمر أو النشر يجب إعداد مفتاح توقيع ثابت محفوظ في GitHub Secrets.
إضافة workflow وحدها لا تعني نجاح بناء APK؛ نتيجة التشغيل في Actions هي المرجع.
